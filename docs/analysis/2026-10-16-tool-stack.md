# Стек інструментів ріелтора й агенції: що централізувати в кабінеті

Дата: 16.10.2026. Доповнює `docs/analysis/2026-10-16-business-analysis.md`. Питання: якими месенджерами, сервісами й додатками щодня користуються ріелтор і власник агенції, навіщо, і що з цього можна звести в один кабінет через інтеграції, а що має лишитись поруч. Прототип (`docs/prototype/rieltor-cabinet.html`) уже містить нові екрани з цього документа.

## Висновок коротко

- Робочий день ріелтора тримається на п'яти речах: телефон, два-три месенджери, портали оголошень, календар і «своя табличка». Усе інше вмикається раз на тиждень або рідше.
- Кабінет має **замінити** табличку, нотатки й нагадування в телефоні, а **підключити** телефон, месенджери, календар, пошту й джерела лідів. Замінювати месенджери чи портали не треба й не вийде.
- Найбільша дірка попередньої версії: ліди. Запити з Otodom, Facebook, сайту і рекомендацій жили в чатах і ніде не фіксувались, бо спек приймав лише клієнтів з договором. Тепер є скринька запитів до договору.
- У Польщі головний месенджер не WhatsApp, а Messenger. Кабінет має підтримувати обидва плюс Telegram і Viber для україномовних клієнтів.
- Дорогі або рідкісні інструменти (e-підпис через API, бухгалтерія, перевірка księgi wieczystej, AML) не інтегруємо на старті: достатньо посилання і статусу в картці.

## 1. Інвентаризація: хто, чим і навіщо

Групування за роботою, яку робить людина, а не за брендом. У дужках частота: Щ щодня, Т щотижня, Р рідко.

## 2. Частотна матриця і відсів

| Частота | Інструменти | Що робимо в кабінеті |
|---|---|---|
| Щодня | Телефон, WhatsApp і Messenger, Telegram і Viber, Otodom і OLX, календар, табличка з клієнтами | Інтегруємо або замінюємо в першу чергу |
| Щотижня | Facebook і Lead Ads, Google Drive, фактури, звіти власнику, брокер, Zoom або Meet | Інтегруємо там, де є дешевий API, решту лишаємо посиланням |
| Рідко | E-підпис, EKW, AML, рекрутинг, Canva | Не інтегруємо. Статус у картці або чекліст |

Відсів: у фокусі перші два рядки. Для третього достатньо, щоб кабінет знав результат (напр. «договір підписано»), а не сам його робив.

## 3. Три кошики

### Кабінет замінює

- Табличку з клієнтами, нотатки й контакти «у телефоні».
- Нагадування в телефоні й папірці.
- Ручний пошук статусів на сайтах забудовників (уже є: Jina, фіди dane.gov.pl).
- Звіти власнику в Sheets (командна дошка, тижневий дайджест, експорт в Excel).
- Чат «хто що робить» у групі команди (стрічка активностей і дошка).

### Кабінет підключає

| Інструмент | Як підключаємо | Що це дає |
|---|---|---|
| Телефон | VoIP-номер (Zadarma або аналог) з API: дзвінок із картки, журнал, запис за згодою | Кожен дзвінок у стрічці клієнта, нотатка з розмови → критерії |
| WhatsApp, Messenger, Telegram, Viber | Етап 1: deep links `wa.me`, `m.me`, `t.me` і сторінка підбірки за токеном. Етап 2–3: Telegram Bot, Messenger Platform, WhatsApp Cloud API | Клієнт відповідає кнопками, відповідь потрапляє в кабінет |
| Google Calendar | OAuth, двостороння синхронізація показів | Показ у звичному календарі ріелтора, зміна часу з обох боків |
| E-mail | Унікальна адреса пересилання на ріелтора (`marta+c123@…`) | Лист від клієнта або банку потрапляє в стрічку |
| Meta Lead Ads | Webhook `leadgen` + Graph API | Лід з Facebook одразу в скриньці запитів |
| Otodom, OLX | Публічного API для вхідних лідів агенції немає, ліди приходять листом. Розбір листів на адресі агенції | Запит з порталу одразу в скриньці з посиланням на оголошення |
| Форма на сайті | Простий POST у кабінет | Запит із сайту в скриньці |
| Telegram-група команди | Bot API (уже в спеку) | Сповіщення й дайджести |
| Fakturownia | API: фактура за комісію з угоди | Власник бачить «виставлено / оплачено» в угоді |
| Autenti | Етап 2+: API від ≈105 € на місяць. На старті лише посилання і ручний статус | Договір підписано дистанційно |
| Кредитний брокер | API не підтверджено. Кнопка «передати брокеру» надсилає анонімізовані критерії листом або в Telegram | Відстеження pre-approval у картці |
| dane.gov.pl, Jina | Уже в спеку | Статуси й ціни лотів |

### Лишається поруч

- Публікація власних оголошень на портали (XML або API Otodom, OLX RE Partner API). Це ядро польських галузевих CRM, але агенція продає лоти забудовників, а не власні об'єкти. Якщо з'явиться потреба, це окремий модуль, не MVP.
- Бухгалтерія, банк, ZUS і податки.
- EKW, Geoportal, CEIDG, KRS: посилання з картки лоту або забудовника й чекліст «перевірено».
- AML: чекліст і дата перевірки в угоді, самі процедури поза кабінетом.
- Canva, сайт агенції, Google Business Profile.
- Нотаріус, Zoom або Meet: посилання на зустріч у показі, не інтеграція.

| Інструмент | API | Трудомісткість | Етап | Вартість | Ризик |
|---|---|---|---|---|---|

| Розбір листів Otodom і OLX | Немає API, лист на e-mail | Дні | 1b | 0 | Формат листа змінюється, тож парсер з перевіркою |
| Форма сайту | Своя | Дні | 1b | 0 | Спам, потрібна капча |
| Google Calendar | Так, OAuth | Тиждень | 1b | 0 | Верифікація OAuth-додатку в Google |
| E-mail пересилання | Cloudflare Email Routing або Gmail API | Тиждень | 1b | 0 | Лист без збігу телефону чи e-mail потрапляє в «нерозібрані» |

| WhatsApp Cloud API | Так | 2 тижні | 3 | За повідомлення | Окремий номер, шаблони, верифікація |
| Fakturownia | Так | Дні | 2 | Тариф Fakturownia | Лише власник |

Ціни й умови сторонніх сервісів перевірити перед стартом, джерела внизу.

## 5. Пропозиції за пріоритетом

1. **Скринька запитів до договору.** Запит з Facebook, Otodom, сайту, рекомендації або вручну: контакт, джерело, канал, згода RODO, статус «новий → контакт → зустріч → договір або відмова». Одна кнопка «Договір підписано» переносить дані у форму клієнта. Власник бачить конверсію запит → договір за джерелом. Це закриває «щось у переписках» із самого початку.
2. **Дзвінок із картки.** Кнопка «Дзвінок» біля телефону, після завершення автоматичний запис у стрічку з тривалістю, поле нотатки, а за згодою клієнта запис розмови → нотатка → критерії. Телефон лишається головним інструментом ріелтора, тож саме тут найбільше втрат інформації.
3. **Google Calendar.** Двостороння синхронізація показів замість лише файлу .ics. Ріелтори вже живуть у календарі.
4. **Messenger як канал на рівні з WhatsApp.** Deep link `m.me` у надсиланні підбірки, пізніше Messenger Platform для сторінки агенції.
5. **E-mail у стрічку.** Унікальна адреса пересилання на ріелтора, лист від клієнта або банку потрапляє в картку.
6. **Договір співпраці в картці.** Статус «немає → згенеровано → надіслано на підпис → підписано», PDF з шаблону, файл у сховищі. Autenti підключити, коли обсяг виправдає тариф.
7. **Фактура за комісію з угоди** через Fakturownia, статуси «виставлено / оплачено» лише власнику.
8. **Передача кредитному брокеру** кнопкою з анонімізованими критеріями й відстеженням pre-approval. Це процес, не інтеграція, доки брокер не дасть API.
9. **Команда без нового чату.** Внутрішній месенджер не будуємо. Telegram-група лишається, кабінет пише туди сповіщення й дайджест.
10. **Сторінка «Інструменти та інтеграції»** в кабінеті, де видно три кошики і що увімкнено. Перемикачі змінюють інтерфейс, щоб власник бачив наслідки.

| Етап | Усередині кабінету | Підключено | Поруч |
|---|---|---|---|

## 7. Питання власнику агенції

1. Чи є зараз реклама у Facebook або Instagram з формою? Хто отримує ці ліди і куди вони потрапляють?
2. На яку адресу приходять запити з Otodom і OLX? Чи одна адреса на агенцію, чи в кожного ріелтора своя?
3. Чи користується хтось VoIP-номером, чи всі дзвонять з особистих? Чи готові дзвонити через номер агенції?
4. Чи готові записувати розмови за згодою клієнта для нотаток?
5. Чи один шаблон договору співпраці на агенцію? Хто його підписує і як (папір, скан, Autenti)?
6. Який календар у ріелторів: Google, Apple, жодного?
7. З яким кредитним брокером працюєте і як передаєте йому клієнта?
